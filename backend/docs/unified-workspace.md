# 统一销售工作空间

2026-09-13：邮件页与业务页共用 `workspace.js` / `workspace.css`，统一主导航、待办入口、客户上下文及移动布局。沿用现有 Django 路由和业务权限，不引入前端框架或新业务模型。

客户详情已补齐独立持续更新：邮件、画像和评分产出后分别展示，保留阅读位置与未保存草稿。读取失败可明确恢复，详见 [逐步展示](live-results.md)。

## 使用路径

- `/` 或 `/#home`：待复核、待跟进、待确认动作、同步异常邮箱，以及按原有优先级排序的邮件客户。
- `/#inbox`：邮件与分析；`/#company/{id}`：客户邮件详情，可直接打开新报价或跟进表单。
- `/business/?company={id}#quotes`：当前客户报价；订单、跟进和动作使用同一客户参数，刷新后仍保留身份。
- `?company={id}&create=1#quotes`：只打开带客户预填的表单，打开后消耗 create 参数，不保存或确认记录。
- `/#reviews`、`/#gmail`、`/#processing`：复核、邮箱连接及最新批次进度；重复点击复核入口仍可重新打开。
- `/business/?status=open#follow-ups`、`?status=pending_confirmation#actions`：待办卡片跳入实际筛选列表；状态选项来自后端契约。

主导航保留工作台、客户、邮件与分析、跟进、通知，其余功能归入销售业务、沟通与资料、设置与协作。未开放渠道不占主导航，原业务资源仍可访问。

## 客户与统计边界

客户通过 URL 传递并由授权目录核验，不放进 localStorage。不可见客户显示明确错误，不默默切换到其他客户。全局资源不沿用客户筛选。原权限、版本冲突、审阅和确认流程不变。

首页“邮件客户”仅统计有业务邮件的公司；业务页“全部可见客户”还包含手工建档及授权可见客户。业务概览注明覆盖全部可见客户，不随当前客户筛选改变。

待办使用后端总数；异常邮箱只统计各邮箱最新批次的 failed/partial 状态，不等于历史全部异常或 Worker 健康状态。概览在页面进入、业务列表更新、复核完成、同步结束和手动刷新时读取。单项读取失败显示未知和错误，不补零。没有新增定时同步、自动确认或自动重试。
